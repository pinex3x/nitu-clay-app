## 2. 本地开发

需要 Node.js 22 或更新版本，在项目根目录执行：

```bash
npm ci
npm run dev
```

打开 `http://localhost:8080/`，修改后刷新。服务只监听本机 `127.0.0.1`，不是手机局域网预览服务；开发时禁用 Service Worker 离线缓存。Ctrl+C 停止服务。

```bash
npm run check        # 构建、JavaScript 语法和本地模块引用检查
npm test             # 构建并运行 Node 回归测试
npm run format:check # 项目既有格式检查范围
npm run build        # 清理并生成 dist
```

`npm run format` 会重写其配置范围内的文件，使用后检查差异。模型再生成需要额外 Python 依赖和 EGL 环境，普通页面开发不需要安装，详见部署说明。

## 3. 模块边界与数据流

运行链路：`index.html → app.js → resolveRoute → createViews → DOM → bind → mountSculpture`。

| 模块                              | 责任与修改约束                                                                   |
| --------------------------------- | -------------------------------------------------------------------------------- |
| `src/app.js`                      | 可变状态、页面生命周期、事件、制作播放和模拟结算；替换页面前停止动画并销毁旧场景 |
| `src/ui/views.js`                 | 接收最新状态快照，输出页面 HTML；不注册事件或写存储                              |
| `src/data/catalog.js`             | 商品与六道工序示例数据；商品数组索引对应模型编号                                 |
| `src/core/`                       | 路由白名单、DOM 查询/转义和浏览器存储                                            |
| `src/rendering/clay.js`           | 模型解析、Three.js 场景、交互、连续工序和图片降级                                |
| `src/style.css`、`src/index.html` | 页面样式、入口和 PWA 元信息                                                      |
| `src/sw.js`                       | 仅处理注册作用域内的 GET 请求，网络优先并使用本项目缓存                          |
| `public/`                         | 模型、795 张预览帧、设计参考、图标、manifest、Three.js 与许可                    |
| `scripts/`                        | Web 构建/开发/检查，以及可选的 Python 资产生成                                   |

新增页面时同时维护视图、应用渲染映射、路由白名单和事件。路径必须适配 `/nitu-clay-app/`：模块导入以发布后的文件位置解析，模型 fetch 以页面 URL 解析。不要改为指向域名根目录的绝对资源路径。

## 4. 存储和模型约定

浏览器键为 `nitu-app-cart`、`nitu-app-addresses`、`nitu-app-orders`、`nitu-app-favorites`。更换域名不会迁移数据，清除站点数据会删除记录。地址和订单只存于当前浏览器；完整结构校验和写入失败提示尚未实现。

三个模型分别是 0 泥虎、1 玉兔、2 春燕。模型由 JSON 偏移表与 bin 数据组成，包含 Float32 顶点/法线/颜色及 Uint32 索引，并非 glTF。新增模型不能只增加商品名称，还需补齐模型文件、工序/角度图片及编号相关逻辑。

构建先清理 dist，再复制源码与静态资源，并根据产物内容生成缓存版本；npz 中间文件不发布。Worker 激活只删除本项目作用域前缀下的旧版本缓存。`dist/sw.js` 是替换过版本占位符的产物，不应手工修改。

## 5. 验证和提交

自动测试覆盖路由边界、原版默认页面 HTML 回归、PWA 资源完整性、项目子路径、缓存隔离及模拟离线读取。测试中的 Worker 环境是模拟环境，不等于手机实测。

涉及交互、渲染或缓存时，人工检查：三个模型切换，制作播放/暂停/进度，商城筛选与搜索，收藏，加购/数量/移除，虚构地址，模拟下单/支付，刷新后持久化；缓存变化还需检查已访问资源离线读取、未缓存资源失败提示和新版 Worker 激活。正式手机验收至少包含 iOS 和 Android，具体覆盖范围记录在验收报告中。

提交前检查 `git diff`，保留第三方许可，不提交 `.openai/`、`archive/`、依赖、构建产物和凭据。根目录 SHA256SUMS.txt 记录版本文件哈希，增改文件后更新；清单自身除外。仅文档变更检查链接、格式、清单与事实一致性，无需新增业务测试。

推送 main 会触发检查与 Pages 部署，PR 只检查。即使只修改文档，现有工作流仍会运行。回滚使用 revert 提交并正常推送，不强制覆盖历史。

## 6. 小程序后续工作的边界

用户当前决定是“先不开发，只进行可行性分析、成本预估和准备事项说明”。新增本文及小程序评估文档不代表小程序已启动开发。后续开始前需重新确认主体、首版功能、预算和是否保留实时 3D，再进行一个模型的技术验证。
