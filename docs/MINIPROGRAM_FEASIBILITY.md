# 微信小程序可行性、成本与准备清单

评估日期：2026-10-22。本文是需求讨论与预算材料，不是已批准的开发任务或正式报价。

## 1. 当前结论与状态

可以将泥途改写为微信小程序，但当前 Web/PWA 源码不能直接作为小程序上传。建议先评估非遗展示与互动体验版，验证 3D 性能后再决定是否投入完整改写。

- 已交付：原生 JavaScript、Three.js、PWA 网站及 GitHub Pages 自动部署，约 12 个路由页面。
- 当前资源：`public/assets` 合计 26,045,284 字节（约 24.84 MiB），含 795 张 WebP 预览帧；不含 vendor 等其他静态文件。
- 三个模型 bin 分别约 8.10、5.10、3.77 MiB，现有分辨率不能直接作为小程序打包方案，应评估减面、压缩、分包或远程资源。
- 用户尚未注册小程序，暂无 AppID；仓库没有小程序工程，也没有微信开发者工具编译、真机或审核结果。
- 当前授权仅限分析和文档。试装的开发依赖已撤回，没有进行页面改写、上传或提交审核。

既有网站：[正式网址](https://pinex3x.github.io/nitu-clay-app/)；[GitHub 仓库](https://github.com/pinex3x/nitu-clay-app)。

## 2. 可选方案与复用范围

| 方案                  | 能复用什么                     | 主要成本与条件                                                                 |
| --------------------- | ------------------------------ | ------------------------------------------------------------------------------ |
| web-view 嵌入现有网页 | 现有页面与大部分交互           | 受主体权限、业务域名校验、托管和真机兼容性限制；不能仅凭网页已公开就认定可上线 |
| 原生轻量展示版        | 数据、文案、图片和部分业务逻辑 | 改写页面、路由、事件和存储；图片转台替代实时 3D，需要用户明确接受此范围变化    |
| 原生完整互动版        | 数据、模型、工序和部分业务逻辑 | 增加 Canvas/WebGL 适配、材质/动画迁移、资源优化与设备测试                      |
| 原生正式交易版        | 互动版及经过审核的商品资料     | 另建服务端订单、支付、库存、退款、物流及运营管理能力                           |

截至本次查阅，腾讯云官方 web-view 配置指南要求企业版小程序配置业务域名；选择此方案前仍应以目标账号后台权限为准。[腾讯云官方指南](https://cloud.tencent.com/document/product/1301/100434)

原生页面需要将 HTML/CSS/DOM 交互迁移到小程序页面和组件体系。localStorage 需要换成小程序存储，Hash 路由需要换成页面导航；Service Worker、PWA 安装引导及浏览器语音朗读不能假定可直接复用，应分别评估小程序端的实现或替代体验。

微信团队的 [threejs-miniprogram](https://github.com/wechat-miniprogram/threejs-miniprogram) 展示了小程序 WebGL 适配路线，但其 README 标注使用 Three.js 0.108.0。当前网页材质、Shader 和渲染接口不能假定与它直接兼容。本项目尚未选定依赖或承诺某种渲染实现。

GitHub Pages 继续承担现有网页展示；不能预先认定 github.io 地址能满足未来小程序的域名、资源托管和稳定访问要求。

## 3. 工作量与人工预算

假设：复用现有视觉和资产，一名熟练开发者，需求基本稳定，不新增自由捏塑编辑器。展示版与互动版不含账号同步或真实交易，正式交易版按表中扩展范围单独估算。费用按 1,000–2,000 元/人日折算，是测算假设，不是市场报价或本次聊天费用。

| 交付档位   | 范围                                                       | 工作量     | 折算人工预算 |
| ---------- | ---------------------------------------------------------- | ---------- | ------------ |
| 轻量展示版 | 原生页面、图片转台、工序浏览、收藏，无真实交易             | 6–10 人日  | 0.6–2 万元   |
| 完整互动版 | 实时 3D、旋转缩放、制作动画、现有模拟商城                  | 12–20 人日 | 1.2–4 万元   |
| 正式交易版 | 在互动版上增加登录、后台、真实支付、库存、订单、退款和发货 | 30–50 人日 | 3–10 万元    |

完整互动版的工作量拆分如下，合计 12–20 人日：

| 工作                             | 人日 |
| -------------------------------- | ---- |
| 工程搭建与一个模型的 3D 验证     | 1–2  |
| 页面与导航迁移                   | 3–5  |
| 存储、收藏、购物车及模拟订单     | 2–3  |
| 模型优化、制作动画与兼容方案     | 3–5  |
| 真机回归、性能修复与发布材料整理 | 3–5  |

上述 1–2 人日验证已包含在总量中，不重复计费。人日不等于自然日；不包含账号注册、认证/备案、资质补充和平台审核的等待时间。低端设备性能不达标或要求高度还原网页材质时，完整互动版建议另预留 20%–30% 工作量。正式交易版需先明确商品和经营模式再重新估算。

## 4. 平台与运营预算

以下只用于低访问量项目的初步预算，不是已核实的服务报价，不据此购买服务。

| 项目                   | 初步预留           | 适用条件与不确定性                                                       |
| ---------------------- | ------------------ | ------------------------------------------------------------------------ |
| 账号认证/核验          | 数百元级别预算     | 本次未核实到最新官方收费，不判断具体主体必须缴纳哪些费用；以注册后台为准 |
| 独立域名               | 约 50–150 元/年    | 仅在选用自有域名时产生，首年/续费和后缀价格需另查                        |
| 静态资源存储与流量     | 早期约 0–100 元/月 | 是否有免费额度、模型下载量、缓存命中和资源大小都会影响账单，免费并非保证 |
| 交易后台、数据库、备份 | 暂不定价           | 确定交易需求和架构后核算，不包含在静态资源预算中                         |
| 支付手续费             | 依商户签约规则     | 当前模拟支付不收费，也未接入商户能力                                     |
| 持续维护               | 单独安排时间与预算 | 包括平台适配、设备问题、内容更新及交易运营                               |

可以先通过分包和资产精简评估是否减少外部托管；如选择云端资源，再确定域名及服务。大资源的冷启动下载和流量账单是主要变量，不应在方案确定前购买服务器。

## 5. 用户需要准备的事项

| 阶段         | 用户准备                                                                           | 我可以协助的部分                                 |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------ |
| 范围决策     | 个人展示还是经营售卖；图片转台还是实时 3D；预算、时间和目标设备                    | 比较方案、细化范围与验收标准                     |
| 主体与账号   | 在微信公众平台注册，按实际情况选择主体，完成管理员身份验证并取得 AppID             | 整理操作路径，核对工程配置                       |
| 平台要求     | 根据目标账号后台处理认证、备案、服务类目及隐私配置                                 | 整理需要核对的材料和发布检查项，不能代替平台审批 |
| 品牌与内容   | 名称、图标、简介、联系方式；模型/图片/文案使用权；真实人物资料或明确的示例展示策略 | 页面呈现和内容校对                               |
| 测试         | 至少一台 iPhone 和一台 Android，最好包含低性能设备；安排体验者                     | 整理测试步骤、定位日志问题、修复并复测           |
| 发布配合     | 管理员扫码、按需身份核验及最终业务信息确认                                         | 代码打包、预览、测试报告和审核材料准备           |
| 若做真实交易 | 核实主体/类目准入，准备商户能力、商品信息、售后与履约规则                          | 技术接入与测试，不代替商户签约和实际经营         |

个人或企业主体应由实际用途决定，不保证某个类目或功能对所有账号开放。账号注册入口为 [微信公众平台](https://mp.weixin.qq.com/)；届时根据后台最新要求逐项核对。

协作时可以提供 AppID 和所需开发权限；不要把密码、AppSecret、支付密钥或证件材料提交到公开 GitHub 仓库或聊天正文。需要扫码及身份验证时由管理员本人完成。

## 6. 后续建议、验收与发布边界

若用户决定启动开发，建议先批准一个模型的技术验证，再决定完整投入：

1. 选定主体、首版功能和设备范围，确认是否接受 3D 效果调整或图片降级。
2. 在小程序环境测试模型加载、旋转缩放、六道工序变形与彩绘；记录包体、首屏、帧率、内存及反复进出页面的表现。性能数值阈值待设备和方案确定后约定，当前没有实测值。
3. 对比压缩/减面前后造型与花纹，评估分包及远程资源；验证弱网、失败重试、无 WebGL 降级、前后台切换和资源释放。
4. 通过验证后再迁移完整页面与本地模拟流程，在 iOS/Android 真机上回归；若有真实交易，另增服务端和支付专项验收。
5. 材料齐备后上传体验版，完成用户验收，再提交审核；正式版发布取决于账号配置、材料、平台审核和管理员操作，无法预先保证通过日期。

开发者工具模拟器通过不等于真机通过；上传成功不等于审核通过；审核通过后还需确认正式发布状态。现有网站的自动测试和离线验收不能作为小程序测试结果。本文不授权开始以上开发步骤，需用户后续明确启动。
